# DPT Treasury Compliance Layer

> **Prototype compliance layer** — MAS-aligned compliance controls for digital
> asset treasury operations. This is a compliance-**readiness** prototype, NOT a
> licensed payment institution or regulated DPT service provider. All screening,
> KYC, sanctions and Travel Rule data are **simulated**.

## Purpose

The compliance layer sits **between the user's transaction intent and blockchain
execution**:

```
User Intent
  -> Intent Parser            (existing Phase 5)
  -> Transaction Planner      (existing Phase 6/7)
  -> COMPLIANCE LAYER:
       1. Counterparty Screening  (simulated, deterministic)
       2. Transaction Monitoring  (deterministic rules + statistics)
       3. Unified Risk Score 0-100 (screening + monitoring + amount + asset +
                                    policy + travel rule)
       4. Policy Engine           (configurable deterministic policies)
       5. Travel Rule             (simulated information completeness)
  -> Risk Decision:  ALLOW | REVIEW | BLOCK
  -> Human Approval (if required)
  -> Blockchain Execution       (existing Phase 9/10 SmartWallet)
  -> Audit Trail
```

## Trust boundary

- **The LLM NEVER decides** `ALLOW / REVIEW / BLOCK`. It may only *explain* a
  decision and *recommend* actions after the deterministic engine has decided.
- `BLOCK` **prevents execution** (the payment card approval/execution path is
  disabled).
- `REVIEW` requires human approval (existing Phase 10 approval gate).
- `ALLOW` still passes through the existing human approval gate before execution.
- Every decision is written to the audit trail.

## Engines (`frontend/src/lib/compliance/`)

| File | Purpose |
| --- | --- |
| `types.ts` | Domain types (decisions, screening, signals, risk, policy, travel rule, audit) |
| `catalog.ts` | Policies, limits, asset risk, mock counterparty registry, disclaimer |
| `counterparty.ts` | Deterministic counterparty screening (0-100 score → PASS/REVIEW/BLOCK) |
| `monitoring.ts` | Deterministic transaction monitoring signals (amount/frequency/timing/…) |
| `risk.ts` | Unified 0-100 compliance risk score + reasons |
| `policy.ts` | **Policy engine** — deterministic ALLOW/REVIEW/BLOCK aggregation |
| `travelRule.ts` | Simulated Travel Rule completeness workflow |
| `orchestrator.ts` | Runs the full pipeline → `ComplianceAssessment` + audit event |
| `portfolio.ts` | DPT portfolio monitoring (allocation, concentration, reserves, warnings) |
| `explain.ts` | Deterministic explanation (LLM may polish prose only) |
| `schema.ts` | Zod validation for `/api/compliance/assess` |

## Policies (configurable, hard-coded defaults)

`max_single_txn` ($50k), `max_daily_txn` ($100k), `allowed_assets`,
`allowed_networks`, `max_counterparty_exposure` ($150k),
`max_asset_concentration` (20%, stablecoin-exempt), `min_stablecoin_reserve`
(40%), `high_risk_counterparty` (≥70 block / ≥40 review), `travel_rule_required`
(> $1k required, > $10k incomplete = block), `manual_approval_threshold`
($25k), `blocklist`. Aggregation: **BLOCK > REVIEW > ALLOW**.

## API routes

- `POST /api/compliance/assess` — run the full compliance pipeline for a transfer
  (persists to `compliance_audit_log` best-effort; deterministic explanation
  fallback when no Gemini key).
- `GET /api/compliance/audit` — audit trail with filters
  (date / customer / txn / risk / decision / asset). Offline → simulated events
  generated by the real engines.
- `GET /api/compliance/portfolio` — deterministic DPT portfolio snapshot.

## UI

- **`/compliance`** — Compliance Dashboard: evaluate-a-transfer tool (preset
  scenarios), full compliance pipe (Intent → Counterparty → Monitoring → Risk →
  Policy → Travel Rule → Decision → Approval → Execution), counterparty
  screening / monitoring / risk / policy / travel rule panels, DPT portfolio
  monitor, recent decisions.
- **`/compliance/audit`** — Audit Log with filters + expandable rows showing the
  "why" behind every decision.
- **Payment flow** — `ComplianceGate` renders inside `PaymentRequestCard` when a
  plan is ready. `BLOCK` disables the approval/execution path.
- **AI advisor** — the financial assistant narration now references the
  compliance layer; per-transfer AI explanations are attached post-decision.
